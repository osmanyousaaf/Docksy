Deploy to your own servers.
It watches them for you, and Claude can fix them.

Docksy is a simple, self-hosted PaaS. You get git-push deploys with zero downtime, monitoring and alerts on by default, backups that are proven to restore, and first-class Claude integration.

Install in 2 minutes → Connect Claude ★ Star on GitHub 
$ curl -fsSL https://raw.githubusercontent.com/osmanyousaaf/docksy/main/install.sh | sudo bash

Three things, done properly

Docksy is deliberately smaller than other PaaS tools. What it does, it does by default.

📈

Monitoring on by default

Live CPU, memory, disk and network for every server and container, from a sub-15 MB agent.

  • 10 alert rules preconfigured
  • Uptime checks auto-created per domain
  • Public status page
  • Discord, Slack, Telegram, email, webhooks
✦

Claude-native

A first-party MCP server and Claude Code plugin. Claude deploys, reads metrics, diagnoses and fixes, always with your consent.

  • 34 MCP tools + deterministic diagnose
  • Skills: deploy, diagnose, incident, dockerize
  • SRE subagent
  • No AI inside Docksy, ever
🚀

Simple, reliable deploys

Push to GitHub and it ships. The old version keeps serving until the new one is healthy.

  • Dockerfile, compose, image or auto-detect
  • Automatic HTTPS (Caddy)
  • One-click rollback
  • One-click databases + verified backups

Your on-call SRE, in the terminal

An alert fires. You type one line. Claude gathers the evidence, explains the cause, and fixes it once you say yes.

> /docksy:diagnose api

● docksy · diagnose(appId: "api")
● docksy · get_server_metrics(prod-1, 1h)   mem ▁▂▂▃▅▆▇██ 97%
● docksy · list_deployments(api)

▸ api: crash-looping, OOM-killed 6× in 10 min
Cause:    deploy a1b2c3d (13:58, "add in-memory cache") → memory 61% → 97%
          → container OOMKilled → 502s on api.example.com   (confidence: high)
Evidence: State.OOMKilled=true · RestartCount 6 · uptime check down since 14:03
Fix:      1. rollback_app(api → 9f8e7d6, yesterday 18:20)  zero downtime, ~30s
          2. cap the cache size, then redeploy
