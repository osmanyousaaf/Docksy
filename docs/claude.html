Claude & MCP

Docksy is built to be operated by Claude. A first-party MCP server and a Claude Code plugin let Claude deploy, read live metrics, diagnose problems and fix them, always with your consent.

No AI inside Docksy. Docksy never calls an LLM and never sends your data anywhere. diagnose is deterministic and returns evidence. Claude, running on your machine with your account, does the reasoning.

1. Create an API token

In Docksy: Settings → API tokens → New token. Pick a scope:

  • full: Claude can deploy, restart, roll back, and so on.
  • read: Claude can look at everything and change nothing. A great way to start.

The token (dsk_…) is shown once. The Claude page (/claude) in your Docksy dashboard shows ready-to-paste snippets that include it.

$ export DOCKSY_URL="https://docksy.example.com"
$ export DOCKSY_TOKEN="dsk_..."

Add these to ~/.zshrc or ~/.bashrc so every session has them.

2. Install the Claude Code plugin (recommended)

# inside Claude Code
/plugin marketplace add osmanyousaaf/docksy
/plugin install docksy@docksy

Restart Claude Code (or run /reload-plugins), then check that /mcp lists docksy as connected. The plugin bundles:

Or: MCP server only

For Claude Code without the plugin:

$ claude mcp add docksy --env DOCKSY_URL=https://docksy.example.com --env DOCKSY_TOKEN=dsk_... -- npx -y @crovenai/docksy-mcp

For Claude Desktop, or any MCP client that uses a JSON config:

{
  "mcpServers": {
    "docksy": {
      "command": "npx",
      "args": ["-y", "@crovenai/docksy-mcp"],
      "env": { "DOCKSY_URL": "https://docksy.example.com", "DOCKSY_TOKEN": "dsk_..." }
    }
  }
}

With the Docksy CLI installed, docksy mcp runs the same server in-process using your CLI login. For clients that prefer HTTP, docksy-mcp --http serves streamable HTTP on 127.0.0.1 only.

Safety model

  1. Token scope: a read token can't change anything, server-side.
  2. Read-only mode: DOCKSY_READONLY=1 hides every write tool from Claude.
  3. Destructive guard: the three destructive tools refuse to run without confirm: true.
  4. Plugin hook: a PreToolUse hook returns "ask" for those tools, so you always see a permission prompt labelled [plugin:docksy], even in auto mode.
  5. Audit trail: every write is recorded in Docksy's activity log under the token's name.
